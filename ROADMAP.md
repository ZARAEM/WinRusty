# WinRust: Roadmap

(Русская версия: [ROADMAP.ru.md](ROADMAP.ru.md))

Each item says how far it was checked: **tests** (unit tests), **built** (compiles, never run), **ran** (run by hand on a live system), **e2e** (full install/uninstall on a live system).

## Done

### Installer
- One `plugin-launcher.exe` with every plugin embedded (unpacked into Program Files, not %TEMP%), static CRT, dark Win32/GDI window. *ran*
- "Install WinRust" installs what is missing in order (topbar before rust-explorer), updates when everything is there; "Remove all" removes in reverse order. *built*
- A failed install undoes its own changes (not when updating a working copy); original values (WSearch, search box, Explorer settings, services) are saved under `HKLM\SOFTWARE\plugin-launcher\<plugin>` and put back on uninstall; non-fatal errors go to `%ProgramData%\plugin-launcher\install.log`. *built*
- Restore point before install. *built*
- Choose what to install (#7): a checkbox per component in the window, several names or `all` on the command line; a component that fails or is skipped does not stop the rest, the failures are listed at the end. A missing Windows Search service (stripped LTSC builds) is a warning, not an error, for both install and uninstall of rust-search. *built*
- The signed-in user, not the elevated account (#4): if UAC was answered with another administrator, per-user settings (HKCU, scheduled tasks, the PowerShell profile, the rust-search pipe permission, the rs-launcher Run key, debloat's HKCU policies) go to the owner of explorer.exe (or topbar / rust-explorer / rs-shell) in the session, through `HKU\<SID>`. If that user cannot be determined, install stops before writing anything. Uninstall carries on with a warning. *tests (key rewriting), built*
- One button installs what is missing **and** updates what is installed, so running a newer `WinRust.exe` brings its fixes to every plugin (v0.2.1). *built*
- Command line: `list | install <plugin>...|all --yes | update <plugin> | uninstall <plugin> | rollback --yes`, exit codes 0/1/2; the window and the command line call the same functions. Only the read-only commands were run. *ran (partly)*
- `update` and `scripts\update-plugin.ps1`: reinstall from `payload\` on disk without rebuilding the installer. *ran*
- English by default, Русский/English switch in the installer and in the bar menu; the choice is stored in `%ProgramData%\WinRust\lang.txt`. *tests*
- Review fixes (v0.3.0): rs-du keeps its quarantine list next to its exe (admin-only), `payload\` two levels up only from `target\release`, rtaskmgr and rust-explorer save and restore another program's Task Manager / folder settings, rust-search brings Windows Search back before removing its files, DiagTrack is left to debloat, one `reg query` parser with a test. *tests, built*
- Settings without Explorer (Win+I and the bar's menus): Settings is a Store app that opens only while Explorer is the shell, so a hidden helper starts Explorer, waits for its taskbar, opens the page, brings the window to the front (also over a fullscreen game), and puts rust-explorer back when Settings is closed; a hung Settings process is killed first. The bar hides only for fullscreen games and video. *built, ran by hand*
- Code layout: one cargo workspace; the installer split into `install/` (one file per plugin), `cli.rs`, `ui.rs`; shared `winrust-common` crate (language switch, MFT reader); one `payload.txt` list for the build and the scripts; CI on GitHub Actions. *tests*

### Plugins
- **rust-search**: NTFS search service + Alt+Space; disables WSearch, blocks SearchHost.exe, hides the taskbar search box. Right-click a result: rename, recycle bin, "delete permanently + clean the registry" (scan → confirm → delete; registry saved to `%LOCALAPPDATA%\rs-search\registry-backups\*.reg` first). *tests, ran*
- **rtaskmgr-win32**: replaces Task Manager through an IFEO Debugger (`taskmgr.exe` untouched); on a panic writes `%APPDATA%\rtaskmgr\crash.log` and opens the real Taskmgr. *tests, ran*
- **topbar**: Windows 11-style bottom bar instead of the taskbar; `topbar.exe --restore` brings the taskbar back. Installs with it: reshell hotkeys, rs-du, the PowerShell profile block (`src/install/profile.ps1`, Windows PowerShell 5.1 and pwsh 7). *ran; the profile block only on a temporary profile*
- **reshell safety net**: if topbar is not running while the taskbar is hidden, twice in a row (~10 s), it runs `topbar.exe --restore`. *tests; killing topbar was not tried*
- **reshell hotkeys**: Win+D (show desktop) and Win+I (Settings) work without Explorer, like Win+E (v0.2.1). *ran*
- **Styles** (v0.3.0): a gear at the left end of the bar switches Normal / Terminal / Floating dock / Tiling; the bar, rust-explorer and the search window repaint at once (a broadcast message, `%ProgramData%\WinRust\style.txt`). The dock reserves no screen space and slides away from maximized windows; Tiling puts the bar at the top and can tile the windows. *ran*
- **topbar look** (v0.3.0): the network icon is drawn (Wi-Fi arcs by signal, a cross when offline, "!" when there is no internet, per Windows' connectivity hint); new Wi-Fi panel (status, connected card with its own Disconnect button, saved/open networks, rows fade in); text-only menus with key hints; input language picker (left click on ENG/RUS); the tray flyout fades in and its chevron turns. *ran*
- **Volume mixer** (fork): a left click on the speaker opens a per-app mixer in the manner of EarTrumpet: the master level, then every app that plays sound with its own slider, mute (click its icon) and a live peak meter inside the slider; the output devices are listed below and a click makes one the default. The wheel over an app's row changes that app, a middle click on the speaker mutes, a right click opens the quick panel as before. Shortcuts: the first eight apps and six devices, no scrolling; switching the device goes through the undocumented `IPolicyConfig`. *tests (names, meter decay), built; never run on Windows*
- **Dragging the bar's buttons** (fork, #6): hold an app button and drag it: pins move among the pins (the order is kept in `%APPDATA%\topbar-pins.txt`), window buttons among the window buttons (until they close). The neighbours glide aside, and the whole row glides instead of jumping when a window opens or closes. App buttons now act when the mouse button comes up. A middle click or Shift+click on a running app starts another instance, like the Windows taskbar (a middle click used to close the window). *tests (drop slot, saved order, glide step), built; never run on Windows*
- **Window previews** (fork): resting the pointer on a running app's button shows live thumbnails of its windows above the bar (DWM thumbnails, with the window's icon and title); a click switches to that window, the cross or a middle click closes it. Moving along the bar swaps the previews at once. Clicking a button with several windows, none of them in front, shows the previews to pick from instead of raising the first. Shortcut: as many previews as fit across the screen, no scrolling. *tests (thumbnail fit), built; never run on Windows*
- **More of the Windows taskbar** (fork): a window that asks for attention (`FlashWindow`) pulses its button orange, then keeps it lit until the window is opened; buttons appear, disappear and change their active mark the moment the window does (shell hook events, with or without Explorer) instead of at the next half-second poll; the sliver at the far end of the bar shows the desktop and, pressed again, brings the windows back; a right click on Start opens the Win+X menu (system tools, Terminal, Task Manager, Run, Desktop); Ctrl+Shift+click on an app button starts it as administrator. *tests (flash curve), built; never run on Windows*
- **Dragging the tray icons** (fork): the icons kept on the bar can be dragged into another order (saved in `topbar-tray.txt`, the others glide aside); dropped on the chevron an icon goes back into the flyout. Tray icons on the bar now act when the mouse button comes up. *tests (drop slot), built; never run on Windows*
- **One mixed row, and drags that raise a window** (fork): pins and window buttons can now be dragged into any order among each other, as on the Windows 11 taskbar (the pins' own order is saved; a window's place lasts until it closes; a new pin lands after the last pin, a new window at the end). Holding anything dragged from another program (a file, text, a tab) over an app's button for about half a second brings that app's window to the front, so the drop can land in it. *tests (row merge), built; never run on Windows*
- **Peek and progress** (fork): resting the pointer on a window preview for half a second shows that window alone, the others as glass outlines (Aero Peek, through dwmapi's undocumented export 113); when the bar is the shell (no Explorer), a progress an app reports to the taskbar (`ITaskbarList3`: downloads, copies, installs) is drawn along the bottom of its button: green, yellow when paused, red on an error, a sliding piece when indeterminate. Both rest on undocumented Windows internals remembered from other taskbar replacements, not on anything observed here: the first things to verify on a real machine. *tests (progress scale), built; never run on Windows*
- **Recent files, microphone, tray flyout drag** (fork): an app button's right-click menu lists up to five files opened lately that the app is the default program for (from the Recent folder and the file associations; a click opens the file); the mixer has a microphone block (level, mute, and the other microphones to switch to); a tray icon can be dragged out of the chevron flyout onto the bar to keep it there (icons in the flyout now act when the mouse button comes up). *tests (recent item extension), built; never run on Windows*
- **Small taskbar habits** (fork): Shift+right click on an app button opens the window's own system menu; resting on the show-desktop sliver peeks through the windows; a pin that was just started bobs until its window shows; the battery tip says how long is left; a second click in time on a tray icon is sent as a double click, and the pointer passing over an icon is reported to its app; the mixer's microphone slider shows a live level while something records. *built; never run on Windows*
- **Taskbar settings** (fork): the gear menu has three switches kept in `%APPDATA%\topbar-settings.txt`: buttons on the left instead of centered, hide the bar automatically (it reserves no screen space, slides away 0.8 s after the pointer leaves and comes back at the screen edge, for Start, panels and previews), seconds in the clock. *built; never run on Windows*
- **Buttons by app, not by exe** (fork): windows are grouped the way the Windows taskbar groups them: by the identity the window declares (Store apps hosted in ApplicationFrameHost, web apps installed from a browser, separate browser profiles), else its packaged process, else its exe; pins that name such an identity take exactly that app's windows. Unpinned windows of one app now share one button (before: a button per window), and that button keeps its place while any of the app's windows is open. Windows of other virtual desktops were already left out (they are cloaked). *tests (pin matching), built; never run on Windows*
- **Notifications from tray apps** (fork): what an app announces through its tray icon (`Shell_NotifyIcon` with `NIF_INFO`, the classic balloon) pops up above the clock for a few seconds (icon, title, text) and is kept in a list of the last 30: right click on the clock, a dot in the clock's corner while there are unread ones. A click on the popup or a list entry tells the app; "Do not disturb" keeps them in the list only, and nothing pops up over a fullscreen app. Toasts that modern apps send straight to the Windows notification platform are not seen (see Next). *tests (popup fade), built; never run on Windows*
- **Now playing, and a real Bluetooth switch** (fork): the mixer shows what is playing (title, artist, from the system media session every player reports to) with previous / play-pause / next; the Bluetooth tile of the quick panel switches the radio on and off and shows its state (it opened Settings before; it still does on a PC without Bluetooth). Both ask the Windows Runtime on worker threads, so the panels never wait. *built; never run on Windows*
- **Keyboard, and order inside the tray flyout** (fork): Win+T walks the app buttons (arrows move, Enter or Space presses, Esc leaves; previews follow), Win+B opens the hidden tray icons, and with the gear menu's "Win+number switches apps" on, Win+1..9 press the first nine buttons (off by default: reshell uses Win+1/2/3 for desktops). Icons inside the tray flyout can be dragged onto one another to reorder them (`topbar-tray-order.txt`). The remaining English-only tips of the bar have Russian text. Not done: picking one of several windows from the previews by keyboard, and screen-reader (UI Automation) support. *built; never run on Windows*
- **Appearance** (fork): "Windows colours" in the gear menu makes the normal style follow the Windows light / dark mode and accent colour, for every WinRust program (shared palette code; off by default; checked every two seconds); "Translucent bar" lets the windows behind show through (plain opacity, not blurred acrylic); the bar is per-monitor DPI aware and resizes at once when the display scale changes. Not done: high contrast themes, right-to-left layout, acrylic blur. *tests (palette contrast), built; never run on Windows*
- **Overflow, status icons, more clocks, scrolling previews** (fork): when the app buttons would get narrower than 30 px the last ones move behind a "…" button with a menu; a microphone icon shows after the tray icons while an app records (click: the privacy page) and an eject icon while a removable drive is plugged in (click: the classic Safely Remove Hardware dialog, which works without Explorer); the clock's tip lists the additional clocks set up in Windows; the mouse wheel scrolls the previews when a button has more windows than fit across the screen. *tests (overflow fit, time zone record), built; never run on Windows*
- **rust-explorer**: file manager (tabs, icons, IFileOperation copy/paste/delete, shell context menu, drag and drop), draws the desktop, turns off Explorer as the shell with `rs-shell --overlay` (90 s after sign-in at the latest: Windows 26300 no longer writes the autostart markers it used to wait for, v0.2.1), trims services. *tests, ran*
- **rs-du**: disk cleaner (MFT analysis, caches, `target`/`node_modules`, recycle bin, 30-day quarantine), started from the bar menu. *tests*
- **wiztree**: disk-usage treemap from the MFT. *tests (layout only); not run on a live disk*
- **photoview**: WIC photo viewer, EXIF rotation, "Open with" entry. *ran; EXIF orientations 5 and 7 not checked*
- **debloat**: services and policies (telemetry, Copilot, Recall, ads, Edge background), old values in `%ProgramData%\winrust-debloat\undo.txt`, `--undo`. *dry run ran; `--apply`/`--undo` not run*
- **purge**: removes the bundled Store apps (installed and provisioned) and the telemetry scheduled tasks like Tiny11 does; OneDrive and Edge only with `--onedrive` / `--edge`. IRREVERSIBLE, a log in `%ProgramData%\winrust-purge
emoved.txt`. `purge.exe` lists, `--ask` asks for YES (the bar's right-click menu), `--apply` removes. Protected names (Store, Settings, Start, runtimes) are tested. *tests, dry run ran; `--apply` not run*

## Next (in order)
0. **Phones and safe removal in rust-explorer** (#2): not started, too big for a quick fix. (a) MTP/PTP phones have no drive letter, so they need the Windows Portable Devices API (`IPortableDeviceManager`, `IPortableDeviceContent`, enumerate objects, read and write through `IPortableDeviceResources` streams) behind a second "file system" in rust-explorer next to the path-based one; copy, paste, delete and drag and drop have to be redone on it. (b) Safe removal: a tray icon in topbar (it already hosts tray icons) that lists removable drives, and `CM_Request_Device_Eject` on the device node of the chosen drive (flush first, report "in use" with the process that holds it). (b) is the smaller half and works for USB sticks and disks; (a) is what the issue is mostly about. Needs a real phone and a USB stick to test: nothing here can be checked by unit tests alone.
0. **Run the fork's bar changes on Windows**: the mixer, the button dragging and the window previews were written and type-checked on Linux (`cargo check --target x86_64-pc-windows-msvc`), nothing more. Check first: the mixer with several apps playing, switching the output device, a drag with one pin, a drag while a window closes, previews of minimized and of elevated windows, the shell hook events while Explorer is also running, every entry of the Win+X menu.
0. **Closer to the Windows taskbar** (fork), in this order: (d) overlay badges on buttons (`ITaskbarList3::SetOverlayIcon`: the icon arrives through shared memory in an undocumented message), and progress while Explorer is also running; (e) the rest of a jump list: an app's own tasks and pinned items (its `AutomaticDestinations` / `CustomDestinations` stores), and recent files for apps that are not the default program for them; (f) a bar on every monitor; (g) toasts of modern apps in the notification list (the supported reader, `UserNotificationListener`, is for packaged apps with the user's consent: the bar would need a package identity); (i) moving one app to another output device (Windows keeps that behind the undocumented `IAudioPolicyConfig`).
0. **More motion** (fork): the minimized / restored state of a button, the tray icons and the tooltips still change at once; window open/close could fade the button out as well as in.
1. **Test on a clean Windows 11 VM**: install, uninstall, rollback, reboot, for each plugin. Nothing has been checked on another machine yet.
2. **One undo journal for every plugin**: each change (registry value, service, file) written as "before → after" before it is made; uninstall and rollback replay it backwards. Replaces the hand-written uninstall of each plugin. Needs step 1 first, and a migration for installs made by the current version.
3. **Registry through the Win32 API** (`RegGetValueW`/`RegSetValueExW`) instead of running `reg.exe` and parsing its output.
4. **Releases**: SHA-256 next to the exe, version in the window, update check.
5. **Code signing** (removes the SmartScreen warning and part of the antivirus false positives).
6. **PowerShell profile**: optionally install rg/fd/bat/eza/zoxide through winget (a checkbox in the topbar settings).
7. **chrome-rs**: a real install once the browser is ready (see `plugins/chrome-rs/ROADMAP.md`).
8. **Win+S / Start button** open rust-search instead of Windows Search (risky, a separate decision).
9. **Non-NTFS drives** in rust-search (skipped today).

## Known limitations
- System components are disabled or bypassed (reversibly), not removed: deleting `taskmgr.exe` or Windows Search outright would break system protection.
- Administrator rights are required.
- Win+S and Start still open Windows Search.
